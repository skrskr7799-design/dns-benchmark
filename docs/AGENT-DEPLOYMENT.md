# Agent deployment (protocol 2)
Use Agents → Подключить агент / Установка агента на VPS. The wizard downloads the same Compose as deploy/compose.agent.yaml plus an origin-only agent.env and a selected DNS allowlist. It never places enrollment tokens in downloaded files. All actions on the VPS remain manual. Use Bash on a new agent directory. For existing installations preserve agent-data, identity, spool, controller origin, and all local approvals.

The agent uses the current edge image by default; NDC_AGENT_IMAGE can pin a verified digest. Protocol 2 is the Compose default; protocol 1 can be explicitly selected only for legacy controller compatibility. The image's inherited controller HTTP healthcheck is disabled for the agent (no listener); the authoritative status is Agents → Online with recent heartbeat. Memory/PID limits are provisional, not physical load evidence.

Controller requires verified HTTPS. Use a private NetBird-reachable reverse proxy, valid DNS name/certificate and firewall. First-run setup of the controller must already be complete. Use exact HTTPS NDC_ORIGIN on controller when using browser through the proxy; normal HTTPS cookies must be secure. Do not disable TLS checks. For private CA put only public CA certificate in agent-data, set NDC_AGENT_CA_FILE=/data/controller-ca.pem, and for probe target private CA separately NDC_CA_FILE if needed. The controller CA need not be the peer CA. Do not expose HTTP 8099 or agent credentials over WAN.

Download files from the wizard, transfer to VPS using a trusted channel, and follow its commands. Create a distinct 10-minute invitation per node. On enrollment the token is consumed and removed, identity.json persists. Check docker compose --env-file agent.env -f compose.agent.yaml logs --tail=40 agent, then Online in UI. Do not share identity, spool, token or private keys. If the invitation expired or was consumed but identity was not saved, rotate in UI and re-enroll on that same VPS; stop the agent before rotating, preserve old private files for recovery, never copy identities to other nodes. For ordinary updates use pull/up -d without a fresh invitation.

First acceptance: two agents (e.g. London and Finland), shared allowlist, Agents → Распределённый тест → https://cloudflare-dns.com/dns-query → Cold → IPv4 → 5 → choose both → Запустить сравнение. Check complete series, actual protocol/IP, and export JSON. No inbound ports required. Online does not attest probe success. Different DNS anycast sites can share IP.

Remote TCP/TLS/HTTP/Route require explicit allowed-probes.json and matching CIDRs on both agents, plus any private destination in NDC_ALLOWED_CIDRS. No broad automatic approvals; see NIP-05.md. Direct RTT/Throughput requires independent mTLS leaves and exact peer direction/traffic policy; no port publication or host-network mode is enabled by this Compose. Test these separately after ordinary DNS works. Controller Compose now passes optional feature flags and lab/atlas settings; defaults remain off. Existing CasaOS deployments require manually applying environment settings, do not overwrite unrelated settings.

Known pending: actual CasaOS/NetBird/VPS verification, peak memory, convenience setup for peer mTLS, and mobile full-page visual review. No physical deployment was performed.
